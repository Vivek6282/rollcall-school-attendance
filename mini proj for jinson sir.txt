## BACKEND
settings.py: AUTH_USER_MODEL="core.User"; INSTALLED_APPS includes admin, auth, contenttypes, sessions, messages, staticfiles, rest_framework, core; ALLOWED_HOSTS=["*"]; MEDIA_ROOT=BASE_DIR/"media"; MEDIA_URL="/media/"; DRF DEFAULT_AUTHENTICATION_CLASSES = JWTAuthentication only; DEFAULT_PERMISSION_CLASSES = IsAuthenticated; SIMPLE_JWT ACCESS_TOKEN_LIFETIME = 1 day (no refresh flow needed on the client); TIME_ZONE="UTC"; USE_TZ=True.

models.py:
- User(AbstractUser): role CharField choices admin/teacher/student, default student; classroom FK -> Classroom, null/blank, related_name="students", on_delete SET_NULL.
- Classroom: name (unique), grade (CharField), teacher FK -> User null, related_name="classes", limit_choices_to role=teacher, on_delete SET_NULL.
- Attendance: student FK User (related_name="attendance", CASCADE), classroom FK, date DateField, status choices present/absent/late/excused, marked_by FK User null SET_NULL related_name="+", created_at auto. Meta unique_together (student, date), ordering ["-date"].
- LeaveRequest: student FK (CASCADE), date, reason TextField, document FileField(upload_to="leaves/%Y/%m/", blank=True), status pending/approved/rejected default pending, created_at. ordering ["-created_at"].
Define Classroom before User OR use the string reference "core.Classroom" to avoid ordering errors.

serializers.py: UserSerializer (id, username, first_name, last_name, email, role, classroom, password write_only, required=False; create/update call set_password when a password is given; role "admin" sets is_staff=is_superuser=True). ClassroomSerializer (+ read-only teacher_name, student_count). AttendanceSerializer (+ read-only student_name). LeaveRequestSerializer (+ read-only student_name; student and status read-only for students). A TokenObtainPairSerializer subclass adds role and username to the token AND to the response body.

views.py (ViewSets + DefaultRouter, all under /api/):
- POST /api/auth/login/ -> custom TokenObtainPairView
- GET /api/me/ -> current user serialized
- /api/users/ ModelViewSet: admin full CRUD; teacher read-only students in their classes; filter ?role= & ?classroom=
- /api/classes/ ModelViewSet: admin write; teacher reads own classes; student reads own class
- /api/attendance/ ModelViewSet: student reads only own; teacher CRUD only for their classes; admin all. Filters ?classroom= ?date= ?student=. perform_create sets marked_by.
- POST /api/attendance/bulk/ (@action detail=False) body {classroom, date, records:[{student, status}]} -> update_or_create per record inside transaction.atomic; teacher must own the class (else 403).
- /api/leaves/ ModelViewSet with MultiPartParser+FormParser+JSONParser: student creates (student=request.user) and lists own; teacher lists leaves of students in their classes and can PATCH status; on "approved", update_or_create Attendance(status="excused") for that date. admin all.
- GET /api/analytics/ (admin only, else 403): { totals:{students, teachers, classes, records, overall_rate}, per_student:[{id, name, classroom, present, absent, late, excused, rate}], per_class:[{name, rate}], trend:[{date, rate}] for last 30 days }. rate = (present+late+excused)/total*100 rounded to 1 decimal, or 0 when total is 0. Use ORM aggregation with Count(filter=Q(...)), no N+1 queries.
Use a small helper for queryset scoping by role. Return 403 via PermissionDenied, never 500.

config/urls.py: admin/ (Django admin at /api/admin/ path is NOT needed; mount Django admin at "django-admin/" but nginx only proxies /api, so it's optional), include router at "api/", plus the login and me routes. Do NOT serve media from Django (nginx does it).

seed.py (idempotent: exit early if User "admin" exists): admin/admin123, teachers t.sharma/teach123 and t.okafor/teach123, 2 classrooms ("Grade 8 - Sunflower", "Grade 9 - Oak"), 10 students s1..s10 / stud123 with realistic names split across classes, and attendance for the last 20 weekdays with a weighted random mix (~85% present) using random.seed(42).
